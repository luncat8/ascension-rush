# Plan 0.3 — Autopilot & Planet Presets

Subject scope: (a) an autopilot that can fly from pad A to pad B and land
safely, usable as an AI "hire" option and as the foundation for the
competitor AI in 0.5; (b) a set of planet presets that vary gravity,
atmosphere, size, and pad layout — pickable from the start menu and saved
with the run. Economy balance constants from 0.2 are per-planet so each
world feels different.

## Files (added / changed)
```
js/planets.js       # planet preset table; replaces hard-coded constants
js/autopilot.js     # guidance + control: ascent, coast, entry, landing
js/mission.js       # extended: contract generation per planet
js/hud.js           # autopilot toggle/status
js/main.js          # planet select on boot (simple canvas menu)
js/physics.js       # generalized to read g0, H_atm, rho0, R, C from planet
js/economy.js       # prices can scale per-planet
```

## Planet presets
A planet preset is a single object. Default presets in `planets.js` (names
are working titles):

```
{
  id, name,
  C,                  // circumference (m); implies R = C/(2π)
  g0,                 // surface gravity m/s²
  rho0,               // sea-level air density kg/m³ (0 = no atmosphere)
  atmScale,           // scale height (m) for exp(-wy/atmScale)
  windMax,            // max horizontal wind speed m/s (0 if no atmo)
  padLayout,          // 'even' | 'clustered' | 'coastal' (simple generators)
  padCount,
  priceFuel,          // $/kg local price
  priceSteel,         // $/kg
  pricePerKgDeliver,  // $/kg
  description         // short one-liner for menu
}
```
Default presets (tuned later):
1. **Verdant** — Earth-like, `g0≈9.81`, thick atmosphere, even pad layout,
   baseline prices. The starting / tutorial world.
2. **Tinmoon** — tiny airless moon, low g (≈1.6), no drag, very cheap
   fuel per kg but lower delivery reward; tight landing tolerances
   (no air to slow you).
3. **Cinder** — super-Earth, high g (≈18), dense atmosphere, expensive
   fuel, high reward; punishing on low-strength builds.
4. **Gossamer** — gas-giant moon with extremely thick atmosphere (high
   drag, low terminal velocity), medium g; drag can slow descent but raises
   dynamic pressure. No vehicle lift or thermal-protection simulation is
   assumed in 0.3.

For 0.3 the planet is chosen once at session start from a canvas menu
(list the presets, Enter/click to select). The selected planet replaces
the global constants in `constants.js`; all modules read from
`game.planet` instead of `R.CONSTANTS.*`.

Wind is optional and off by default. Model it as horizontal air velocity,
not an extra force: compute aerodynamic drag from the rocket's velocity
relative to the wind. Keep gust magnitudes small and seeded so autopilot
experiments are reproducible.

## Autopilot design
The autopilot must fly the *same* physics the player uses (no cheating — it
can only read the rocket state, issue heading/throttle/stage commands, and
touch down on the target pad). It is a state-machine controller.

### Autopilot inputs (read-only)
- Rocket state `(wx, wy, vx, vy, heading)`, current stage info (fuel,
  thrustMax, isp), total mass.
- Planet params (`g`, `rho` functions).
- Target pad position `(target_wx, 0)` with wrap-aware downrange
  distance `dx = wrapDelta(target_wx - wx)`.

### Autopilot outputs
- Commanded heading `cmd_h`.
- Commanded throttle `cmd_t ∈ [0,1]`.
- Commanded stage `cmd_stage : bool` (pulse true to stage).
The control layer in `controls.js` will drive the rocket with these exactly
like player input; player can toggle autopilot on/off in flight.

### Phases (guidance state machine)
1. **PRELAUNCH** — wait for the builder's explicit Launch command; toggling
   AP on the pad must not bypass build/mission confirmation. Set target and
   estimate required dV before ignition.
2. **VERTICAL_CLIMB** — first few seconds: hold `heading = 0`, full
   throttle, to clear thick atmosphere and avoid immediate aerodynamic
   stress.
3. **GRAVITY_TURN** — pitch over toward target heading (east if `dx > 0`,
   west otherwise) by a target flight-path-angle schedule; aim for a
   prescribed pitch as a function of altitude (e.g. linear from 90° to 30°
   between 1 km and 15 km on Verdant; scaled per planet).
4. **COAST** — shut down engine once the predicted trajectory (simple
   drag-free projectile under inverse-square gravity over flat-wrap
   geometry) reaches the target within a tolerance. During coast, point
   roughly prograde for minimal drag; perform a mid-course correction
   burn if cross-range error grows.
5. **ENTRY_BRAKE** (only when the predicted path can safely use an
   atmosphere) — monitor dynamic pressure and passive drag deceleration.
   With the initial fixed-Cd point-mass model, changing heading does not
   change drag or create lift; do not claim nose-up steering can brake. If a
   later attitude-dependent drag model is added, validate its limits
   separately. Use thrust braking or abort when the trajectory is not
   recoverable.
6. **TERMINAL_DESCENT** — when near the target (within a few km horizontally
   and low altitude), switch to a controlled vertical descent: cancel
   horizontal velocity with a slight tilt, then throttle to hold a target
   descent rate (e.g. `vy_target = -5 m/s`). A simple PID on altitude
   error and vertical velocity (use pre-allocated PID state, no per-frame
   allocations).
7. **LANDING_TOUCHDOWN** — reduce vertical and horizontal speed below
   `vSafe` / `vSafeH`; cut thrust only when the predicted remaining descent
   reaches the pad within those touchdown limits. Avoid a last-second
   powered "hop" that would increase impact speed.
8. **ABORT** — if predicted landing point drifts outside pad radius with no
   fuel/power to recover, cut throttle and crash deliberately (better
   than exploding randomly); triggers failure in mission.

Staging: during climb/turn, monitor fuel in current stage; auto-stage when
fuel is exhausted OR when the current stage has too little thrust-to-weight
to continue the profile (i.e. when a stage has done its job).

### PID tuning notes
- Provide a small generic PID helper in `util.js` (no allocations after
  construction, reset method). Reuse two or three PID instances
  (vertical rate, horizontal error, heading) across the whole flight.
- Default gains are per-planet preset (heavier planets need tighter
  vertical gains; airless worlds need gentler corrections because drag
  doesn't damp overshoot).
- Experiments (`experiments/autopilot-tune.js`) can run headless physics
  batches under node to tune gains per preset without the browser.

### Player-facing
- HUD gets an "AP" button/keypress (suggest **A**) to toggle autopilot.
- When on, show the current AP phase name ("CLIMB", "COAST", "LAND") and a
  small projected landing-point marker on the ground (screen-space tick
  on the ground strip).
- Player can take over at any time; AP re-engages cleanly (recomputes
  phase from current state).
- Autopilot is not free (economy hook for 0.4 / 0.5): e.g. a small
  service fee per flight, or a percentage of delivery reward (simple:
  subtract `AUTOPILOT_FEE = PRICE_DELIVER_PER_KG * payload * 0.1` at
  delivery).

## Contract/mission generation (first cut)
When landed on a pad, the mission selector lists 2–3 available contracts
to other pads, each with a payload mass and reward (reward =
`pricePerKgDeliver * payload * distanceFactor`, where distanceFactor
scales up for longer flights). This replaces the simple target-picker
from 0.2 and gives variety. Autopilot can be offered as a toggle per
contract.

## Acceptance criteria for 0.3
- Planet-select menu appears at boot; choosing Verdant reproduces the 0.2
  behavior (baseline physics unchanged).
- At least three other presets are selectable and feel distinct (different
  launch weights, different required fuel, different drag).
- On a defined reference build, autopilot safely completes at least 9 of 10
  headless runs for each preset's supported standard contracts. Contract
  generation must mark routes outside that build's tested fuel/trajectory
  envelope as unavailable or higher-risk; do not count physically unreachable
  contracts as controller failures.
- Player can toggle autopilot mid-flight and take control without state
  corruption.
- AP fee is deducted on delivery; cash accounting works.
- Projected landing marker moves visibly during coast and converges on the
  target pad during descent.
