# Worklog — 0.3.6 Operations deck review

Review pass over 0.3.5 before starting 0.4. Three defects, all found by reading
the shipped code and probing it under node rather than by a failing test.

## Fixed
- **The autopilot fee was charged for hand-flown legs.** `mission.beginLeg`
  hard-coded `flight.usedAutopilot = true` and nothing ever cleared it, so a
  player who took over with `A` still paid 10 % of the reward, and the debrief
  claimed "(Balanced profile)". `autopilot.toggle()` now clears the flag when
  it disables the autopilot in flight: the fee is for the guidance, not for the
  launch. Programmatic enable/disable (mission start and end) leaves the flag
  alone, so an ordinary autopilot delivery still pays.
- **A rocket type could be edited while its instance was flying.** The mission
  was dispatched against a template snapshot (`order.type`) but the return leg
  is priced and prepared from the live type, and the workshop could rewrite it
  mid-flight: halving the tanks turned a healthy return leg into
  `PAYLOAD EXCEEDS CAPACITY` with `sendReturnLeg` refusing, and the capacity
  the deck quoted changed under the player. `operations.saveType(typeId, spec)`
  is now the one validated write to an existing type and refuses with
  `TYPE FLYING` while any instance of it is airborne. The builder's save and
  build buttons go through it and abort on the refusal.
- **Growing a type past its stage count wrote past the end of `stages`.** A
  1- or 2-stage type saved with 3 stages crashed on `type.stages[2].fuelMass`.
  `saveType` rebuilds the stage list from the spec instead of overwriting in
  place, so a template can grow.
- `js/rocket.js` lines 283–334 (the stage helpers `nextAliveStageIndex`,
  `activeStage`, `stackThrustAcceleration`, `separateStage`) were one
  indentation level short; re-indented to the repo's single tab.

## Validation
- `experiments/flight-test.js` (+1 assertion family): a manual takeover marks
  the leg hand-flown, pays no fee, logs `autopilotFee: 0` and the debrief does
  not claim one.
- `experiments/builder-test.js` (+5 assertions): a type saved with more stages
  grows and its new stage starts at the minimum tank; `saveType` is refused
  with `TYPE FLYING` while the type's rocket is in the air and the template is
  left as it was.
- All 8 suites pass: 585 assertions (was 574).
- `node experiments/envelope.js verdant 0 balanced` → 12/12 delivered with a
  table identical to `experiments/logs/0.3.5-touchdowns.txt`, so the fixes
  moved no physics.

## Checked and left alone
- A return-mode mission whose landing stack cannot lift the return payload does
  not dead-end: `operations.blockReturn` ends the order, logs `RETURN BLOCKED`
  and leaves the rocket `available` at the pad it landed on, where the next
  dispatch quotes a turnaround that rebuilds the stack. Re-probed after the
  type freeze, since the failure this worklog fixed could produce the same
  symptom from the other side.
- A route offer is a snapshot: while it is on screen the route can stop being
  ready (cash spent, rocket moved) and the card still reads "Route ready". The
  dispatch path re-evaluates and names the reason, so the cost is a stale card
  rather than a wrong flight; recorded here, not patched, because 0.4.1 changes
  what "ready" costs and the offer card has to be revisited anyway.
