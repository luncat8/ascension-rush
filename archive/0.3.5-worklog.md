# Worklog — 0.3.5 Autopilot operations deck

## Plan review
- The plan's fleet status list included a resting `turnaround` state, and the
  cash model put turnaround/refuel charges at touchdown. Those two do not
  survive contact with each other: if the charges land at touchdown, the
  *no refuel* return policy has nowhere to be represented — there is no moment
  left to say "this leg pays nothing". Turnaround and refuel moved to **leg
  preparation** (`operations.preparePlan` → `rocket.restorePlan`), charged on
  the leg that consumes them, and `turnaround` disappeared from the status
  set. Statuses are `available | queued | flying | lost`. Recorded as a
  deviation in the plan's state-transition block.
- The plan said "turnaround is immediate while the game is at the operations
  deck" without pricing the decision. It ships as: preparation quotes
  `{ fuelMass, dryMass }` — fuel to fill and structure to replace — and
  `planCost` prices both at the current fuel/steel rates. A rocket that landed
  on one stage therefore has the missing stages rebuilt at the next refuelled
  leg, at steel price, and the leg that pays records it as `turnaroundCost`.
- "Charge only the fuel loaded" needed a rule for what *loaded* means on a
  used stack. It is `rocket.restorePlan` against the type template: full tanks
  charge nothing extra, a stack missing stages charges for the structure, and
  a stack that already has fuel charges only the difference.
- `structureCost` in the log schema had no definition. It is the steel value of
  the stack actually flown, recorded but **not charged** — capital at risk, so
  0.4 can compute depreciation without re-deriving it from snapshots.
- The plan left the phase name `building` in place while making the builder a
  secondary dialog. Renamed to `deck`; every test that asserted the old name
  was updated rather than keeping both.
- Dispatch is autopilot-only. The plan implied it (routes fly themselves) but
  never said the manual launch path goes away. It does: `mission.beginLeg`
  enables the autopilot, `mission.touchdown` disables it, and `applyBuild` —
  the config-shaped entry point only manual launch used — was deleted from
  `rocket.js`.
- Auto-launch "after the route has completed one successful leg" is enforced
  in the offer itself, not in the toggle: `offer.autoLaunch` is
  `route.autoLaunch && route.completedLegs > 0`, so a route that has never
  delivered always asks, however it is configured.

## Implemented
- **`js/flight-log.js`** (new, 52 lines). Append-only, newest-first, capped at
  `constants.operations.flightLogLimit` (200). `append`, `findById`,
  `countByRoute`, `reset`. No DOM node or formatted string is stored.
- **`js/operations.js`** (new, 925 lines). Types, fleet, mission orders,
  routes, the scheduler, and every state transition. `evaluateLeg` is the
  single source of wait reasons — `PAUSED`, `NO ROCKET AT <PAD>`,
  `ROCKET BUSY`, `PAYLOAD EXCEEDS CAPACITY`, `NEEDS REFUEL`,
  `INSUFFICIENT FUNDS`, `CHOOSE TWO DIFFERENT PADS`, `SIMULATOR BUSY`,
  `RETURN BLOCKED` — and the deck never re-derives them. `run` is gated on a
  `revision` counter so the scheduler only re-evaluates after a command moved
  state, and evaluates into one reusable scratch object.
- **`js/deck.js`** (new, 976 lines). Dispatch / Routes / Flight log views,
  three dialogs (workshop, route type, route review), focus trapping and
  restoration, `aria-live` announcements, and the launch offer with its
  countdown. Opens a dialog by setting `operations.blocked`, which pauses the
  scheduler so automation cannot fire behind the workshop.
- **`js/mission.js`** rewritten around legs: `beginLeg`, `touchdown`,
  `returnBlocked`, `reportReturnBlocked`, `debrief`. `touchdown` classifies the
  leg (`delivered | landed | crashed | return-blocked`), writes
  `game.lastReport`, calls `operations.applyLegResult`, and returns the
  debrief. `estimatedCost` and `nextTargetId` are gone.
- **`js/economy.js`** rewritten as an explicit ledger: `spend`, `earn`,
  `buyRocket`, `refuel`, `turnaround`, `burnFuel`, `beginFlight`,
  `finishFlight`. `cashDelta = revenue − fuelCost − turnaroundCost −
  autopilotFee`, accumulated on the flight record.
- **`js/rocket.js`**: `createStageState`, `captureStageState`,
  `restorePlan`, `launchTwr`, `applyFleetState`. `applyFleetState` is now the
  only path into flight state; `applyBuild` was removed with the manual launch.
- **`js/builder.js`** reduced to the rocket-type workshop (306 lines): edit or
  create a type, preview capacity against the planet's reference, build a fleet
  instance at the pad the workshop was opened for. All scheduling lives in
  `operations`.
- **`js/render.js`**: the active leg is drawn as an arc between its own
  `legFrom`/`legTo` with arrow heads, the departure pad is highlighted, and the
  mission row names the leg (`LEG 1 OF 2`). Panel height 143.
- **`index.html`** rewritten as the operations deck with three dialogs; it is
  now also a test fixture — `experiments/dom.js` parses it, so an id that
  `deck.js` or `builder.js` reaches for but the markup does not define fails a
  test.
- **`css/style.css`**: `.builder-panel` → `.deck`, plus ~330 lines of deck,
  route-row, log-row and dialog styling (882 lines total).
- **`experiments/dom.js`** (new, 326 lines). A forgiving HTML tokenizer and a
  DOM node implementation (`classList`, `dataset`, `appendChild`,
  `querySelectorAll`, `dispatch`, `click`, focus tracking) small enough to read
  and honest enough that the real `index.html` drives the real `deck.js`.

## Bugs the tests caught
- `builder.update()` read a module-local `createStats()` object instead of the
  one `operations.typeStats` returns, so every design showed capacity 0 and
  silently clamped its payload to 0.
- `builder.update()` also called `readInputs()`, which clobbered any draft
  loaded programmatically (open type, planet defaults, planet switch) with the
  previous form values on the first repaint. Input reads now happen only in
  `onInput`.
- `dispatchRoute` called `cancelOffer()` *after* dispatching, which re-set
  `dismissedRouteId` for the route that had just flown, so it was never offered
  again. Acting on an offer now clears it without recording a dismissal.
- Dismissing an offer was a permanent veto. Added `forgetDismissal()`, called by
  every command that expresses intent (dispatch, build, create/save/delete
  route, enable, auto-launch toggle, type change); `refreshRoutes` also clears
  it when a route stops being ready.
- `hasRocketAt` counted `lost` instances, so a pad whose only rocket had
  crashed reported `ROCKET BUSY`.

## Also noted, not changed
- `planets.copyInto` still shares the preset's `flight` object by reference
  between worlds using the same preset (carried over from 0.3.4). Untouched
  here because nothing in 0.3.5 tunes a world in place.
- `localStorage` persistence stayed deferred. Nothing in the run path depends
  on storage; `operations.initialize` is the whole per-world reset.

`operations.js` is the seam the contract board plugs into, and the flight log
already carries `revenue`, `fuelCost`, `structureCost`, `turnaroundCost`,
`autopilotFee` and `cashDelta` per leg, so route profitability needs aggregation
rather than new instrumentation. Two smaller follow-ups belong with it: the
builder warning deferred out of 0.3.4 (naming a stack whose later stages cannot
hold the rocket up) now has a place to live in the route review dialog, and
turnaround's flat steel price is the obvious first thing a parts catalog should
replace.
