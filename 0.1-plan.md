# Plan 0.1 — World, Rendering Scaffold, Planet & Launch Pads

Subject scope: canvas shell, game-loop scaffolding, wrap-around planet map,
launch pads, coordinate system, camera, log-Y scale, triangle rocket sprite.
No physics, no flight, no economy — only a static world the player can look at
and a placeable rocket triangle. This is the first playable-looking slice.

## Goals
- A single `<canvas id="c">` fills the viewport; no build step; works from
  `file://` via classic `<script>` tags.
- A 2D side-view world where the planet surface occupies the bottom 10 % of
  the screen, wraps horizontally (wrap-X), and supports arbitrary horizontal
  travel with the camera following.
- Vertical (Y) axis uses a logarithmic scale so both near-ground and
  high-altitude distances are visible (see Coordinates below).
- Multiple named launch pads sit on the surface at fixed longitudes; the
  player starts at one and the mission target is another.
- A rocket is rendered as a triangle with a visible heading indicator; no
  motion yet — it sits on the starting pad.

## Files
```
index.html          # updated: loads all scripts in order, sets viewport

js/world.js         # planet surface geometry, pad registry

js/rocket.js        # rocket data model (stub) + drawRocket()

```
Guard every file with `if (typeof module !== 'undefined') module.exports = …`
so they also run under node (for experiments/). Use single-tab indent, LF.

## Coordinates (critical design)
- World coordinates are 2D: `(wx, wy)`. `wy` is altitude above the surface, in
  meters, **always ≥ 0**. `wx` is horizontal distance east of an arbitrary
  origin, in meters; can be any real number.
- Wrap-X: the planet has a circumference `C` (meters). All horizontal
  distances and positions are taken modulo `C`, but keep `wx` unbounded for
  the camera and compute the shortest signed delta with
  `wrapDelta(dx) = ((dx + C/2) mod C) - C/2`.
- Y is log-scaled in screen space. Define screen Y from bottom of canvas up:
  `screenY = H - H_ground - f(wy)`, where `H_ground = 0.1 * H` is the ground
  strip height and `f(wy)` is a log mapping from world meters to pixels.
  Recommended mapping: let `wy0 = 1` (1 meter = reference altitude) and
  `wyMax = 1e6` (edge of visible space ≈ 1000 km). Use
  `f(wy) = (H - H_ground) * log1p(wy / wyScale) / log1p(wyMax / wyScale)`
  with `wyScale` chosen so launch pads and the rocket triangle (~10 m tall)
  are clearly visible on the ground strip. Exact constants are tuned in
  `constants.js` and left as named values.
- Because Y is logarithmic, straight world-space lines are **not** straight
  on screen. Rocket and velocity vectors must be transformed through
  `coords.worldToScreen` for rendering; physics (Plan 0.2) runs purely in
  world coordinates.
- Rocket angle (heading) is in radians, 0 = straight up, positive = clockwise
  (east). Render the heading indicator as a short line protruding from the
  nose.

## Planet (first pass, extended in 0.3)
For 0.1 the planet has only these parameters (see `constants.js`):
- `C` circumference (m), default ~1 000 000 (≈ small moon; easy to circumnavigate).
- `g0` surface gravity (m/s²), default 9.81.
- `R` implied radius = `C / (2π)` (informational, used later for gravity
  falloff and atmospheric density).
- Atmospheric parameters (scale height, sea-level density, drag coefficient
  defaults) are declared but unused until 0.2 / 0.3.
Surface is a flat line at `wy = 0` in world space, drawn across the ground
strip with simple texture (noise dots or a repeating pattern) to give a
sense of motion. No terrain height variation in 0.1 — pads sit directly on
y=0.

## Launch Pads
- Defined as a sorted array of pad objects: `{ id, name, wx, color }`.
- Default set (tunable): at least 4 pads distributed around the planet, e.g.
  Homeport (0 m), Eastport (C/4), Farport (C/2), Westport (3C/4).
- Rendered as a small filled rectangle on the ground strip with the name
  above it. The "active" pad (start or target) gets a ring/marker.
- Two pointers live in game state: `currentPadId` (where the rocket sits or
  launched from) and `targetPadId` (mission destination, highlighted).

## Rocket (visual stub)
- Data shape (will grow in 0.2):
  ```
  rocket = {
    wx, wy, vx, vy,      // position (m, m) and velocity (m/s)
    heading,             // radians, 0=up
    onGround: true,      // sitting on pad
    padId,               // which pad
    stages: [ ... ]      // filled properly in 0.2
  }
  ```
- For 0.1 the rocket is placed on the current pad with `wy = 0`, `vx=vy=0`,
  `heading = 0`.
- Drawn as an isosceles triangle, nose pointing along `heading`, with a
  short velocity/heading tick and a small flame stub (non-animated) that
  will be wired to thrust in 0.2. Size on screen is derived from a
  world-space length (e.g. 20 m tall at default build) mapped through the
  log-Y transform — so at very high altitude the triangle still reads as a
  triangle but shrinks appropriately.

## Camera
- Follows `(rocket.wx, rocket.wy)`. Horizontal position: camera center wx is
  set so the rocket sits at 1/3 from the left of the canvas (gives forward
  view when moving east); wrap-aware so drawing never pops. Vertical
  position: center on the rocket but clamp so ground strip stays visible and
  the top of the atmosphere (wyMax) is reachable.
- Provide a `camera.project(wx, wy) → {sx, sy}` and `camera.unproject(sx, sy) → {wx, wy}`
  pair used by both rendering and mouse input (0.2 uses unproject for
  heading control).

## Input (stub for 0.1)
- Resize handler: resize canvas to `window.innerWidth/innerHeight` with
  `devicePixelRatio` taken into account (scale the backing store, not CSS
  size).
- Mouse move is captured but only used for a debug crosshair at the
  unprojected world point — heading control lands in 0.2.
- Keys `Space`, `Ctrl`, `Shift` log a console message in 0.1 so the input
  routing is verified.

## Render loop
- Single `requestAnimationFrame` loop in `main.js`:
  1. compute `dt` capped (e.g. min 1/120 s, max 1/30 s to avoid spiral of
     death on tab refocus);
  2. `update(dt)` — no-op in 0.1, rocket stays on pad;
  3. `render()` — sky gradient, ground strip, pads (with wrap-around draw so
     pads just off-camera render on the other side), rocket, HUD shell
     (mission: "Homeport → Eastport", altitude readout, velocity = 0).
- Use a single preallocated scratch object/array pool per `util.js`; no
  per-frame allocations in `render()` or `update()`.

## Acceptance criteria for 0.1
- Page loads from `file://` with no console errors on any modern browser.
- Canvas fills the window; resizing works.
- Ground strip occupies the bottom ~10 % of the screen; pads are visible
  with names; one pad is highlighted as target.
- Rocket triangle sits on the starting pad pointing up, with a visible
  heading tick.
- Moving the mouse shows a crosshair (or projected marker) so the
  world↔screen transform is visibly correct, especially near the ground
  (fine detail) vs high up (compressed).
- No physics yet; rocket does not move. Pressing Space/Ctrl/Shift logs to
  console proving input routing.
