# Plan 0.2 — Rocket Physics, Stage Builder & Flight Controls

Subject scope: rocket construction UI/state, staged rocket physics (mass,
thrust, Tsiolkovsky, stage separation), manual flight controls (mouse
heading, Space for stage, Ctrl/Shift for throttle), pad-to-pad flight
win/loss conditions, basic cost readout. Builds on 0.1.

## Goals
- Player can configure a rocket before launch: number of stages (1–3), per
  stage size (fuel mass), structural strength/quality slider, payload mass.
- Launch from the current pad and fly manually. Thrust vector follows mouse
  heading; Space stages (drops current stage, ignites next); Ctrl/Shift
  adjust throttle.
- Realistic-enough physics: point-mass rocket under gravity + thrust +
  atmospheric drag; logarithmic Y preserved from 0.1; wrap-X.
- Cost model: fuel consumed, steel used for hull/stages, payload bonus on
  successful landing; running totals in the HUD.
- Landing judgement: contact with ground while within a pad's tolerance
  (low vertical speed, near-horizontal velocity, close to pad wx) counts as
  a successful delivery. Otherwise a crash with a damage/report screen
  (full damage model lands in 0.5).

## Rocket data model
```
stage = {
  fuelMass,        // kg, current
  fuelMax,         // kg, set at build
  dryMass,         // kg, derived from tank+engine (steel + fixed parts)
  thrustMax,       // N, sea-level rated thrust; vacuum thrust scaled in 0.3
  ispSea, ispVac,  // s, used with atmospheric pressure to compute exhaust v
  burnRateMax,     // kg/s at full throttle (derived from thrust / (g0*isp))
  strength,        // 0..1 build quality slider; affects failure chance (0.5)
  alive            // boolean; false after separation
}
rocket = {
  wx, wy, vx, vy, heading,
  stages,          // array, index 0 is first to burn (bottom)
  currentStage,    // index
  throttle,        // 0..1
  onGround, padId,
  payloadMass,     // kg, set at build
  // stats
  fuelSpentCash, steelSpentCash,
  launched, landed, crashed
}
```
`dryMass` scales with `fuelMax` (tanks have mass proportional to fuel they
hold) plus a fixed engine/turbopump mass per stage. Exact coefficients go in
`constants.js` and are tuned in 0.4.

### Mass & Tsiolkovsky
- Instantaneous mass `m = payloadMass + sum over alive stages (dryMass + fuelMass)`.
- Thrust magnitude `T = thrustMax * throttle` of the current alive stage,
  directed along `heading` (0 = up in world frame).
- Fuel burn `dm/dt = -burnRateMax * throttle` for the current stage; clamped
  so `fuelMass ≥ 0`. When `fuelMass` hits 0 and throttle is up, nothing
  happens — the player must press Space to stage (or coast).
- Stage separation (Space): set `currentStage.alive = false`, increment
  `currentStage`, ignite immediately if that stage exists. If no next stage
  the rocket becomes a glider/payload.

### Atmospheric model (simple for 0.2; refined in 0.3)
- Density `rho(wy) = rho0 * exp(-wy / H_atm)`; `rho0 = 1.225 kg/m³`,
  `H_atm` a scale height constant from `constants.js`.
- Drag: `a_drag = -0.5 * rho * v_mag * A * Cd / m * v_vec`, where `A` is a
  reference area and `Cd ≈ 0.04` for a streamlined rocket (constants).
- Isp interpolation: `isp = ispSea + (ispVac - ispSea) * (1 - rho/rho0)` so
  engines are more efficient in vacuum.

### Gravity (first pass; refined with planet presets in 0.3)
For 0.2 use flat-planet gravity pointing straight down with magnitude
`g(wy) = g0 * (R/(R+wy))²`. Near the ground this is `g0`; at altitude it
falls off, which matters for orbital-ish hops but we are not modeling
orbit — circumnavigation is via suborbital arcs across wrap-X.

### Integrator
Use semi-implicit Euler with a fixed sub-step (e.g. 120 Hz = 8.33 ms) inside
each `requestAnimationFrame` `dt` to keep stability at high thrust. Clamp
acceleration magnitude to a named design limit. Update order: apply forces →
acceleration → velocity → position. Keep rocket `wx` unbounded across the
wrap seam for continuous camera motion; normalize only when looking up a pad
or price, and use the shared positive-modulo `wrapDelta` for shortest-route
distances. This preserves the world-coordinate contract established in 0.1.

## Controls
- **Mouse move**: set `heading` so the rocket nose points from the rocket
  screen position toward the mouse cursor in world space (unproject mouse
  to world, compute angle relative to rocket, convert to our 0=up
  convention). When `onGround`, heading is locked to 0 (straight up) until
  liftoff; allow a small gimbal range after liftoff (e.g. ±30° from
  velocity vector) until 0.3 adds proper aerodynamic forces.
- **Space**: stage separation (as above). Ignored if not in flight or
  current stage has fuel remaining (you *can* hot-stage but by default
  disallow it unless shift-held? — keep simple: always stage, even with
  fuel, for player freedom; warn in HUD).
- **Shift**: increase throttle by a rate (e.g. 1.0 / 0.5 s → full in half a
  second), clamped to `[0, 1]`.
- **Ctrl**: decrease throttle by the same rate.
- On the pad: mouse/keys do nothing until player clicks a "Launch" button
  exposed by the builder UI.

## Builder UI
A side panel shown only when `onGround`:
- Target pad selector (dropdown over `world.pads` excluding current).
- Payload mass slider (0..max). Max is derived from remaining lift
  capacity; show estimated dV for the current config.
- Stage count 1–3; for each stage: fuel mass slider (tied to a visual of
  rocket length), strength slider 0.5..1.0 (low strength = cheaper but
  higher failure rate — hooked fully in 0.5; for 0.2 low strength just
  shows a warning).
- Live readouts: total takeoff mass, total steel mass (sum of dryMasses),
  total fuel mass, estimated cost (using `economy.js` unit prices),
  estimated delta-V via Tsiolkovsky (rough, uses averaged isp).
- A big **Launch** button that commits the build (so the player can't
  re-configure mid-flight) and sets `onGround = false`, `throttle = 1` for
  an initial liftoff.

## Mission / Landing
- Launch sets `rocket.launched = true`, `mission.departedPadId`,
  `mission.targetPadId`.
- While flying, track ground proximity. When `wy` drops to 0 or below:
  - Find the nearest pad within `landingRadius` (e.g. 50 m, constant).
  - Check landing safety: `|vy| < vSafe` (e.g. 8 m/s) and `|vx| < vSafeH`
    (e.g. 15 m/s).
  - If on target pad and safe → success: add payload reward, settle repair
    cost (0 in 0.2 unless crash), show "Delivered" overlay with cash delta
    and offer "Return to builder / New mission".
  - If on a non-target pad but safe → "landed elsewhere" consolation: no
    reward, fuel/steel already spent are sunk cost; let player Relaunch to
    continue.
  - If not near any pad or unsafe → crash: rocket destroyed, payload lost,
    reset to builder with the cash spent subtracted (i.e. you ate the
    cost). For 0.2 damage/repair is binary; 0.5 will add partial failures.
- Pads are "solid" only within their radius; the rest of the ground is
  just terrain you crash into (same rule as off-pad).

## Economy (first cut)
`economy.js` exposes unit prices as named constants tuned later in 0.4:
- `PRICE_FUEL` = $ per kg of fuel (e.g. RP-1/LOX analog).
- `PRICE_STEEL` = $ per kg of dry-mass structure (stages + engines).
- `PRICE_DELIVER_PER_KG` = $ per kg of payload delivered to the correct
  target pad.
- In this prototype, charge the configured hull/build cost at launch, fuel
  for the amount actually burned (`dm` per sub-step × price), and the reward
  at delivery; record each as a separate ledger entry. Cash persists across
  flights (`game.cash`). Plan 0.4 replaces the prototype hull charge with
  persistent parts, so reused hardware must not be charged at full replacement
  cost again.

## HUD
Top/side overlay drawn in canvas (no HTML overlay over canvas for game
state, except the builder panel):
- Altitude, horizontal speed, vertical speed, heading (°).
- Current stage number, fuel remaining in current stage as bar.
- Throttle bar (0–100 %).
- Cash delta (+/-) and running balance.
- Target pad name + distance (shortest wrap-X distance).
- Throttle/stage key hints.

## Acceptance criteria for 0.2
- From a cold start at Homeport, player can open the builder, pick a
  target, configure a 1–3 stage rocket, and launch.
- Rocket lifts off, mouse steers the nose, Shift/Ctrl change engine power
  with visible throttle response, Space drops a stage and ignites the
  next.
- Suborbital hop reaches the other side of the planet; wrap-X means
  flying east long enough brings you back.
- Player can land softly on the target pad and see a positive cash delta
  (if payload delivered), or crash and lose costs.
- Log-Y scale from 0.1 remains stable in flight; triangle rocket is
  readable at altitude and close to ground.
- Builder's dV estimate roughly matches actual flight performance (within
  ~20 % — 0.4 tuning will tighten).
