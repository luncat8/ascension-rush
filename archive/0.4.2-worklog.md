# Worklog — 0.4.2 Parts catalog

## Review of the previous commit (0.3.6 / 0.4.1)

Read the whole tree the single commit shipped and re-ran every suite. 0.4.1
(pad markets + contracts) is complete and correct: `js/market.js` is deterministic
and seeded, the contract life (assign/fulfil/release/expire) is sound, and
`economy.priceFuel/Steel/Delivery` are pad-scoped. Two genuine issues, both fixed:

- **`rocket.separateStage` was not indented to the repo's single-tab standard**
  while every other top-level function was. The 0.4.1 worklog claimed to have
  re-indented the stage helpers but this one was missed; its body (`var stage`,
  etc.) also sat at column 0. Re-indented it and the dangling comment above
  `nextAliveStageIndex` so the file is one style throughout.
- **`operations.js` `addType`/`saveType` built stage objects as `{ fuelMass,
  strength }`; the new stage model needs `engineId`/`tankId`/`fairingId`.**

## Plan review (0.4.2 in 0.4-plan.md)

Rewrote the 0.4.2 section. The earlier draft had a real ambiguity: the `tank`
part definition listed a `strength` field *and* the plan said strength stayed a
slider, so a stage would have had strength in two places. Clarified that **strength
is a per-stage slider, not a tank property** — a tank only carries
`massPerFuelMass`/`costPerMass`, and the player still dials its built strength.
Also pinned down the mass/cost formulas, that Isp and thrust now come from the
engine, that `restorePlan`/turnaround price the parts a leg replaced, the fairing
drag model (`referenceArea` threaded through `aerodynamics.calculate`, jettison at
`fairingAltitude`), and the validation (envelope byte-identical, new parts-test).

## Implemented
- **`constants.parts`** (in `constants.js`): engines/tanks/fairings tables plus
  `defaultEngineId`/`defaultTankId`/`fairingAltitude`/structure factors. The
  default engine (`e-standard`) and tank (`t-standard`) carry the exact 0.3
  numbers — 72 N/kg, base 60 kg, 150 N/kg, 0.075, Isp 265/330 — so a reference
  build flies identically.
- **`js/parts.js`** (new): `engine`/`tank`/`fairing` lookups (default-resolving),
  `sanitizeStage` (fills missing ids so a `{ fuelMass, strength }` config or a
  pre-catalog type still loads), `stageBreakdown` (engine + tank + optional
  fairing, top stage only), `stageThrust`, `typeStructureCost` (turnaround
  pricing through each part's `costPerMass`), `typeBuildCost`.
- **`rocket.js`** reads parts for `stageDryMass`/`stageThrust`/`evaluateBuild`/
  `applyFleetState`/`restorePlan`/`stackMass`: Isp from the engine, thrust from
  `thrustPerFuelMass`, dry mass from `massPerFuelMass` and the structure factor.
  Fairing state (`fairingAttached`/`fairingMass`/`fairingDragFraction`) is set in
  `applyFleetState`.
- **`aerodynamics.js`** takes an optional `referenceArea`; **`physics.js`** shrinks
  drag while a fairing is attached and sheds it (mass + drag) above
  `fairingAltitude`. Default builds carry no fairing, so the envelope is unchanged.
- **`operations.js`** type stages carry `engineId`/`tankId`/`fairingId`;
  `addType`/`saveType`/`snapshotType`/`restoreTypeFromSnapshot` keep them; the
  dispatch cost path is unchanged (preparation-based, refuel-gated).
- **`builder.js` + `index.html` + `css`**: per-stage engine/tank/fairing pickers
  and a structure breakdown (engines / tanks / fairing kg) in the workshop; a
  fairing is selectable only on the top stage. The builder cost now prices from the
  parts (`typeBuildCost`), which equals the old steel cost for the default parts.

## Validation
- **New `experiments/parts-test.js`** (10 assertions families): catalog well-formed
  and unique ids; default `stageBreakdown` equals the 0.3 formula for every tested
  fuel/strength; `rocket.stageDryMass` matches when only `{ fuelMass, strength }`
  is given; a fairing adds exactly its mass; `sanitizeStage` fills and preserves
  ids; `typeStructureCost` prices the stages a turnaround replaces; an alternative
  engine/tank changes thrust/mass; `typeBuildCost` is full structure + full fuel.
- All 10 suites pass: 8 carried over + parts-test (new) ≈ (counts rose from 684 to
  724: parts-test added 40, builder/operations/render-smoke kept counterparts).
- **Physics did not move.** `node experiments/envelope.js <world> 0 balanced` is
  12/12 on verdant, cinder, tinmoon and aquarex, with the same maxima as
  `experiments/logs/0.3.5-touchdowns.txt` (default parts == 0.3 constants).
- **`experiments/build-sweep.js` (60/100 builds per world, seed 1): 0
  regressions**; balanced/gentle still recover the flights the dry baseline loses.

## Bug the work caught
The first wiring charged the turnaround by *computing* `typeStructureCost` instead
of *spending* it, so the structure money never left the ledger (cash short by
exactly the turnaround). The turnaround must go through `economy.turnaround` (a
spend) and stay gated by `preparation.dryMass` so a no-refuel return charges
nothing — reverted that path to the preparation-based charge.

# Review pass over the shipped 0.4.2 (same increment, second commit)

Read the increment against its own plan and re-measured it. The catalog, the
continuity rule and the fairing model were sound; four things the plan promised
were not actually wired, and two were wrong in a way a test could catch.

## Bugs found and fixed

- **`operations.typeStats` never copied the part ids into its scratch config**, so
  every number derived from it — `dryMass`, `thrustMax`, `deltaV`, `payloadLimit`,
  the deck's capacity, the `PAYLOAD_OVER` gate and the build price — was measured
  with the *default* engine and tank whatever the player had picked. Measured on a
  `e-boost`/`t-light`/fairing build: the workshop quoted **665.5 kg / 30 240 N /
  Δv 4 281** (the reference build's numbers) where the parts give **864.6 kg /
  36 960 N / Δv 3 247**; `operations.typeTwr` *did* read the real parts, so one
  panel showed a booster's TWR next to a standard engine's mass. `typeStats` now
  copies `engineId`/`tankId`/`fairingId` and the scratch stages declare them.
- **`costPerMass` reached nothing.** The only function that folded it,
  `parts.typeStructureCost`, was called from nowhere in `js/` (only from
  `parts-test`); `typeBuildCost`, `economy.buyRocket`, the turnaround and
  `structureCost` all priced raw kg × steel. So the booster's 1.2, the vacuum
  engine's 1.4, the light tank's 1.1 and the reinforced tank's 0.9 existed only in
  the catalog. Replaced with one notion — **structure value in steel-kg**
  (`parts.stageStructureValue` / `typeStructureValue` / `restoreStructureValue`)
  — that every money figure is computed from: `typeBuildCost`, the turnaround
  (`restorePlan` now returns `plan.structureValue`, `planCost` and
  `economy.turnaround` charge it, still gated so a no-refuel leg buys nothing) and
  `structureCost`. `economy.estimateBuildCost` was the duplicate of that arithmetic
  reading the wrong input, and is gone; `economy.buyRocket(game, structureValue,
  fuelMass, padId)` is charged from the parts.
- **The workshop's bill of materials summed all three stage slots**, so a one- or
  two-stage build reported the mass of stages it does not have, next to a total
  that (correctly) did not include them. It now counts only the stages in the
  build, and prices them (engines / tanks / fairing / fuel) instead of only
  weighing them, so the line adds up to the price the build button charges.
- **A fairing outlived the stage carrying it.** Separating the top stage below
  `fairingAltitude` dropped its mass with the stage but left `fairingAttached`
  true, so drag stayed multiplied by `dragFraction` for a fairing that was gone,
  and the later jettison subtracted the mass from a dead stage. `physics.step` now
  drops the fairing as soon as its stage is not alive.
- Style, the same class the first pass fixed in `rocket.js`: `constants.parts`,
  `constants.economy` and `constants.market` sat at column 0 in a file whose other
  blocks use a single tab (bodies re-indented to match), and the mid-function
  `var`s in `rocket.applyFleetState`, `aerodynamics.calculate`, `physics.step` and
  `builder.update` moved to the top of their functions. An unused `settings` local
  in `applyFleetState` was dropped.

## Also

- The dispatch card now has a `PARTS` row naming the parts the selected type is
  built from (`Standard engine ×3 · Standard tank ×3 · Standard fairing`), and its
  build quote and structure quote come from `parts.typeBuildCost` and
  `evaluation.structureValue` instead of a mass × steel, so the card and the
  workshop can no longer disagree.
- `builder.readInputs` normalises an empty fairing picker to `null` rather than
  leaving `''` in the draft.

## Validation

- `experiments/parts-test.js` extended (34 → 69 `assert` calls): structure value
  equals dry mass for the default parts and prices
  each alternative at its own `costPerMass`; `typeStats` measures the engine, tank
  and fairing a type carries and does not keep the previous build's parts; a
  fairing lowers payload capacity by exactly its mass; `buildRocket` charges
  exactly `typeBuildCost` and a premium build costs more than its weight in steel;
  a turnaround prices the parts it replaces while a no-refuel leg prices nothing;
  and three fairing-in-flight cases (jettison at altitude, separation below it,
  no fairing at all). Each new test was checked to fail with its fix reverted.
- `aerodynamics-test` now covers the `referenceArea` argument (an explicit area
  scales drag by exactly that ratio; passing none is the constant) and
  `builder-test` covers the pickers, the fairing-only-on-top rule, the priced bill
  of materials and the fairing dropping off a stage removed from the build.
- **Physics did not move.** All 48 reference route rows from
  `experiments/envelope.js <world> 0 balanced` are byte-identical to
  `experiments/logs/0.3.5-touchdowns.txt`, and the 8 gentle/off summary lines
  match too. `build-sweep 60 1`: **0 regressions**, same 218/226/229/230.
- All 10 suites pass.
